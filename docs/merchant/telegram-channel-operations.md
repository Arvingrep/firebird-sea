# 平台商家频道运营指南（培训 + 功能更新）

面向：平台运营（频道主）、负责发公告的开发/运维同学。
读完能独立完成：建频道 → 配置发帖机器人 → 按规范发培训与更新内容 → 让商家加入并保持触达。

> **这个频道是什么、不是什么**
>
> - **是**：平台官方运营的**单一**频道，面向全体商家。内容三类：**商家培训**（后台怎么用、
>   常见问题）、**功能更新**（新功能上线、规则调整）、**维护通知**（停机、发布窗口）。
> - **不是**：商家的店铺展示位，也不承担任何交易、订单、商品同步职能。
>   商家各自的经营内容与平台频道**无关**——不要把「让商家建自己的频道」当成入驻流程的一环。
> - **单向广播**：频道无评论（或仅运营管控讨论组），商家反馈走客服/工单，不在这里收集。

---

## 0. 前置条件

| 项 | 要求 | 谁负责 |
| :--- | :--- | :--- |
| Telegram 账号 | 用**平台官方账号**持有频道，不要用任何个人的私人号——人员变动时频道会跟着走 | 运营 |
| 发帖机器人 | 由平台创建（BotFather），用户名形如 `@xxx_bot`。运维用 `curl "https://api.telegram.org/bot<TOKEN>/getMe"` 取 `result.username` 确认（`services/api/src/addrShareRoute.js` 同法） | 运维 |
| 商家触达物料 | 频道邀请链接 / `t.me/<username>`，要能贴进商家后台与 TMA | 运营 |

## 1. 创建频道（平台侧，一次性）

1. Telegram → **New Channel**。
2. 命名：`<平台名> 商家中心`。**不要**带商圈/品牌后缀——它是全平台一个频道，不是某家店的。
3. 选**公开频道**（有 `@username`）：商家能搜索到、链接能印在后台与物料上。
   username 定了就不要改——后台页面、培训材料里印的链接都会失效。
4. 简介（About）写三样：
   - 本频道用途一句话（「商家培训与平台功能更新，不发广告」）；
   - **商家后台入口**：`https://<域名>/wmsj/login.php`；
   - 商家客服/反馈渠道。
5. 关闭「Sign messages」以外的多余设置；**不开评论**（省得变成客服群）。

---

## 2. 配置发帖机器人

机器人负责自动发**功能更新公告**（将来 CI 发布后自动推送），培训贴可以人工发。

1. 频道 → **Administrators** → **Add Administrator** → 搜机器人用户名。
2. **只勾四项**：

   | 权限 | 用途 |
   | :--- | :--- |
   | Post Messages | 发更新公告、维护通知 |
   | Edit Messages | 发布窗口变动时改旧公告（改帖而非删了重发，时间线可追溯） |
   | Delete Messages | 撤回发错的公告 |
   | Post Media | 截图、操作动图 |

   **不给**：Add New Admins、Ban Users、Manage Video Chats、Remain Anonymous。
   机器人不需要这些权限，多给的每一项都是滥用面。

3. 自检：让机器人往频道发一条测试消息并**编辑**它——Post 和 Edit 都通才算配好。

> **坑**：机器人必须先是频道管理员，平台才能通过它发帖/读 `channel_id`。
> 顺序反了会一直 `chat not found`，很多人误以为是 token 错。
> 频道 id 是负数且以 `-100` 开头（如 `-1001234567890`）；拿到正数那是个人 id。

---

## 3. 让商家加入

这是商家侧**唯一**要做的事——没有任何绑定、配置或开通流程：

1. 把频道链接（`https://t.me/<username>`）放到两处固定位置：
   - 商家后台登录页 / 首页公告位；
   - 新商家开通邮件/欢迎消息里。
2. 商家点链接 → Join，即完成。新商家入驻 SOP 里加一行「加入官方商家频道」即可。
3. 不用拉人头、不统计谁加入了。频道是广播，覆盖面靠曝光位，不靠点名。

---

## 4. 内容规范（三类帖，固定模板）

混着发会让频道变成没人看的公告板，所以每类帖固定长相，商家扫一眼就知道这条要不要细读。

### 4.1 功能更新（最重要的一类）

```text
🚀 更新｜订单详情新增配送地图

现在商家已接单/配送中的订单，可以在订单详情看到：
骑手实时位置、剩余距离，并可直接唤起导航。

商家需要做什么：无需操作，自动生效。
生效时间：已上线（canary 已更新，生产 XX 月 XX 日）。
详情：https://<域名>/docs/xxx   ← 可选
```

要点：

- **标题一句话说清「新了什么」**，正文回答商家唯一关心的问题：「我要不要做什么」。
  大多数更新答案是「无需操作」，直说。
- 每条更新**必须写生效时间**。canary 和生产不是同时发布的，别让商家以为立刻全量生效。
- 与发布节奏挂钩：合并进 `main` 的用户可见变更，在生产部署完成后当天发。
  建议在 PR 描述里就写好这条公告草稿，发布后直接粘贴。

### 4.2 商家培训

```text
📖 培训｜改价为什么 TMA 里没变？

菜品价格只在商家后台生效：/wmsj/shop/waimaiFoodList.php
TMA 每次打开都读后台实时数据，不存在要刷新的「缓存」。
如果你在频道/别处看到不同价格，以后台为准。
```

要点：

- 一次只讲一个问题，从**商家真实踩过的坑**里选题（客服记录、FAQ）。
- 操作步骤直接给后台路径（后台路径实测可用：`/wmsj/login.php` 登录、
  `/wmsj/shop/waimaiFoodList.php` 菜品、`/wmsj/shop/waimaiShop.php` 店铺信息）。
- 高频问题沉淀成一篇帖子后固定不动，靠频道置顶/话题引用，不要反复重发。

### 4.3 维护通知

```text
🛠 维护｜XX 月 XX 日 02:00–02:30 系统更新

期间下单可能短暂失败，已支付订单不受影响。
```

要点：提前 24 小时发；开始/结束各发一条；写清「对商家的影响是什么」。

### 发帖纪律

- 每周更新公告 ≤ 3 条、培训 ≤ 2 条。没有值得发的内容就**不发**——
  频道价值取决于「每条都有用」，刷屏等于让商家静音。
- 公告发出后 10 分钟内**编辑检查一遍**：链接能点、后台路径能打开、日期没写错。

## 5. 验收清单（平台侧一次性 + 日常各一份）

**开通时：**

- [ ] 频道建在平台官方账号下（不是个人号）
- [ ] 公开频道，`t.me/<username>` 可访问，username 已同步到商家后台与入驻 SOP
- [ ] 简介含：用途一句话、后台入口、反馈渠道
- [ ] 机器人是管理员且只有 4 项权限，实测能发+能编辑
- [ ] 已记录 `channel_id`（`-100` 开头）备将来自动发帖用
- [ ] 置顶一条「频道使用说明」（三类帖是什么、多久更新一次）

**日常（每次发帖）：**

- [ ] 用了对的模板，标题带类别前缀（🚀/📖/🛠）
- [ ] 更新公告写了生效时间与「商家要做什么」
- [ ] 链接与后台路径点开验证过

## 6. 常见问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `400 chat not found` | 机器人还不是频道管理员 | 先加管理员再发帖 |
| `403 bot is not a member…` | 机器人被移出频道 | 重新加管理员 |
| 机器人能发不能改 | 没给 Edit Messages | 补权限 |
| 拿到的 id 是正数 | 那是个人 id，不是频道 | 频道 id 是 `-100…` 开头 |
| 改频道名会失效吗 | id 与名字无关，改名不影响机器人/链接外的一切 | 链接会变，已印物料需同步 |
| 商家说没收到更新 | 频道被静音，或 Telegram 通知被系统关了 | 培训贴里教一次「别静音本频道」；重要公告同时发后台公告位，**不要只依赖频道** |

## 7. 与研发流水线的关系

频道内容本身不进 CI。两个将来的自动化方向，**都未实现**，做之前按仓库规则立项：

1. **发布后自动发更新公告**：CI 部署完成后由后端服务调 Bot API 发 4.1 模板。
   届时需新增 `services/api` 内部路由（如 `POST /tg-api/internal/channel-post`），
   必须同步 `docs/api/openapi.yaml`（门禁第 10 项会拦）、带 `services/api/test/` 测试。
2. **后台公告位与频道同源**：商家后台公告从同一份更新记录读取，避免两处内容漂移。

设计取舍见 `docs/internal/AGENT_PIPELINE.md` 第 5d 节。
