# 商家 Telegram 频道入驻指南

面向：新签约商家、负责开通的运营同学。
读完能独立完成：建频道 → 配机器人管理员 → 绑定商户后台 → 同步商品目录。

> **先说清三件事，免得照着做一半卡住**
>
> 1. **频道是「展示位 + 通知位」，不是店铺。** 顾客下单仍在 Telegram Mini App（TMA）里完成，
>    频道负责让老客看到新品/优惠、让新客找到入口。频道里发的东西不进商品库。
> 2. **商品主数据只有一个来源**：商家后台的菜品管理（`/wmsj/shop/waimaiFoodList.php`）。
>    频道内容由它派生，不要反向改。
> 3. **绑定与同步目前是人工步骤**（本文第 3、4 步标注了现状）。仓库里目前**没有**频道绑定表、
>    也没有 Bot 自动发帖服务，所以别指望「填个 ID 就自动同步」——那还没做。

---

## 0. 前置条件

| 项 | 要求 | 谁给 |
| :--- | :--- | :--- |
| 商家后台账号 | 能登录 `/wmsj/login.php`，且已开通外卖模块（能在 `/wmsj/shop/waimaiShop.php` 看到自己的店） | 运营开通 |
| Telegram 账号 | 建议开启两步验证（2FA）。频道归属跟账号走，账号丢了频道就找不回来 | 商家自己 |
| 官方机器人 | 由平台方提供用户名（形如 `@xxx_bot`）。不要自己拿 BotFather 建一个，平台不认 | 运营提供 |
| 频道归属 | 频道必须建在**商家的 Telegram 账号**下，不要建在运营个人号下——后续维护、交接都会变成事故 | 商家自己 |

机器人用户名怎么查：运维用 `curl "https://api.telegram.org/bot<TOKEN>/getMe"`，取 `result.username`。
后端 `services/api/src/addrShareRoute.js` 建立分享链接时也是这么取的，所以这个用户名可信。

## 1. 创建频道

1. Telegram → 菜单 → **New Channel**（新建频道）。
2. 填频道名：`<品牌名> · <商圈>`，与商家后台的店铺名保持一致（例：`KOI Thé · Pasay`）。
   **为什么要一致**：后续对账、客服查单都靠名字对人，名字乱填会让「这家店到底哪个频道」变成考古。
3. 选类型：
   - **公开频道**（有 `@username`）：能被搜索、能直接用 `t.me/<username>` 分享。**建议选这个**。
   - **私有频道**：只能靠邀请链接进。仅用于内部试营业/员工群。
   - 选公开时 username 一旦定了不要频繁改——已经印在物料上的链接会失效（旧链接会 302，但搜索排名会重来）。
4. 频道简介里必须包含三样：营业时间、配送范围、**下单入口**（TMA 深链）。
   下单入口从运营拿，格式形如 `https://t.me/<bot_username>/<app_short_name>`。
5. 头像用品牌 Logo 方图（512×512 以上），不要用菜单照片——频道列表里缩略图很小。

---

## 2. 配置官方机器人管理员

1. 频道 → 右上角 → **Administrators** → **Add Administrator**。
2. 搜索运营给的机器人用户名，添加。
3. **只勾这四项**：

   | 权限 | 用途 |
   | :--- | :--- |
   | Post Messages | 发新品/公告 |
   | Edit Messages | 改价、改营业时间（改旧帖而不是删了重发） |
   | Delete Messages | 下架过期活动 |
   | Post Media（需要发图时） | 菜品图、活动海报 |

   **不要给**：Add New Admins、Ban Users、Manage Video Chats、Remain Anonymous。
   机器人不需要这些权限，多给的每一项都是被滥用的面。
4. 加完确认：频道管理员列表里能看到机器人，且其权限是上表四项。

> **坑**：机器人**必须先是管理员**，平台才能读到这个频道的 `channel_id`。
> 顺序反了会一直拿到 `chat not found`，很多人会误以为是 token 错。

## 3. 绑定商户后台（当前为登记制）

**现状**：商家后台没有「绑定 Telegram 频道」的页面，`webroot/wmsj/` 与
`webroot/api/handlers/waimai.class.php` 里都没有 Telegram 相关代码。所以这一步目前是：

1. 取频道 `channel_id`：在频道里发一条任意消息 → 转发给 `@userinfobot`，
   或由运维用机器人 `getUpdates` 读。**公开频道的 id 是负数且以 `-100` 开头**（如 `-1001234567890`）。
   如果拿到的是正数，那多半是你的个人号 id，不是频道。
2. 记下频道链接：`https://t.me/<username>`（私有频道记邀请链接）。
3. 把这三项报给运营登记：**商家后台店铺 ID / channel_id / 频道链接**。
   店铺 ID 在后台地址栏里能看到（`/wmsj/shop/waimaiShop.php?id=...`）。
4. 运营登记后，商家在频道里发一条测试消息，确认机器人能编辑它（验证权限真的给到了）。

**为什么不做成让商家自己填 channel_id**：手填 13 位负数极易错一位，错了要到发不出消息才发现；
更麻烦的是没有校验——A 商家可以把 B 的频道填进来。真要产品化，应做成
**一次性绑定码**：后台生成 6 位码 → 商家在频道里发 `/bind <码>` → 机器人校验「发消息的是该频道管理员」
才落库。这样归属由 Telegram 自己证明，不靠人填。

## 4. 同步商品目录

**现状**：商品主数据在商家后台维护，频道内容**没有自动同步**。

### 4.1 唯一数据源：商家后台

- 菜品与分类：`/wmsj/shop/waimaiFoodList.php`（分类在 `waimaiFoodType.php`）
- 店铺信息（营业时间、起送价、配送费）：`/wmsj/shop/waimaiShop.php`

改价、下架、改营业时间**只在这里改**。频道帖子是它的投影，投影不会自动跟着变。

### 4.2 三种同步方式，按投入从低到高

| 方式 | 怎么做 | 适合 | 代价 |
| :--- | :--- | :--- | :--- |
| **手工发帖** | 运营照菜品列表编辑成图文，发到频道 | 单店、上新不频繁 | 每次上新 10–20 分钟；容易与后台不一致 |
| **模板批量** | 运营用固定模板（菜品名/价格/图）批量生成后粘进频道 | 多店、每周固定上新 | 需要人盯；模板与后台字段要人工对齐 |
| **Bot 定时推送**（未实现） | 定时读菜品变更，只推 diff | 门店多、想省人力 | 要新增后端服务；需处理刷屏与去重 |

**如果选了 Bot 推送，触发策略建议**：只推「价格变化 / 上下架 / 新增」，且单频道每小时最多一条汇总，
不要全量重刷——频道是关注者的信息流，刷屏等于让用户静音。

### 4.3 一致性检查（每次同步后做）

- 频道里标的价 = 后台 `/wmsj/shop/waimaiFoodList.php` 里的价
- 频道里没提「已售罄」的菜，在 TMA 里能加购
- 营业时间与后台一致（这条最常错，因为改了后台忘了改频道简介）

## 5. 验收清单

开通完成后逐条打勾，缺一条就不算开通：

- [ ] 频道名与商家后台店铺名一致
- [ ] 频道是公开频道，`t.me/<username>` 能打开
- [ ] 简介包含：营业时间、配送范围、TMA 下单入口
- [ ] 机器人是管理员，且权限只有 4 项（发/编辑/删/发媒体）
- [ ] 平台已登记 `channel_id`（-100 开头）与频道链接
- [ ] 用机器人成功发过一条消息，并成功**编辑**过它（证明 Post + Edit 都通）
- [ ] 频道内商品价格与后台一致
- [ ] 商家知道「改价只在后台改，频道要手动跟」

## 6. 常见问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `403 bot is not a member of the channel chat` | 机器人被移出频道，或没加为管理员 | 重新加管理员，确认权限 |
| `400 chat not found` | 机器人还不是管理员（读不到频道）；或 `channel_id` 填错 | 先加管理员，再取 id |
| 拿到的是正数 id | 那是用户 id，不是频道 | 公开频道 id 是 `-100…` 开头 |
| 机器人能发帖不能改帖 | 没给 Edit Messages | 补权限 |
| 私有频道读不到 | 私有频道需邀请链接，且机器人也要在频道内 | 改用公开频道做对外展示 |
| 改了频道名，id 变了吗 | **不变**。id 与名字无关，改名不影响绑定 | 无需重新登记 |

## 7. 和研发流水线的关系

频道内容本身不进 CI（它不在代码里）。但**如果要给「绑定/同步」加后端接口**，必须按仓库现行规则走：

1. 新增路由要同步 `docs/api/openapi.yaml`，否则确定性门禁第 10 项（API 契约同步）会 FAIL；
2. 同一 PR 必须带 `services/api/test/` 下的测试；
3. 写库的操作按现有惯例做归属校验（参考 `services/api/src/fbProxy.js` 的 `ownershipPrecheck`）。

细节见 `docs/internal/AGENT_PIPELINE.md` 第 5d 节与 `docs/api/openapi.yaml` 文件头。
